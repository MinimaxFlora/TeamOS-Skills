# 诊断细则（步骤1.4）

> 按需加载：执行步骤1.4 时读本文件。骨架见 `SKILL.md` 的「1.4 AI 痕迹检测」。本文件不含规则本身，只有判据与映射。

## 七维定论表

脚本只给词/句式计数，测不出结构与内容维度；以下 7 维必须逐项定论（**禁止仅给综合评分**）：

| # | 维度 | 检测方法 | 阈值 |
|---|---|---|---|
| D1 | 连接词密度 | 统计"此外/然而/因此/综上所述/值得注意的是/总而言之/首先/其次/最后" | >3 次/千字 → `[!]` |
| D2 | 句式同质化 | 连续 3 句以上完整"主谓宾"或"不仅…而且…"对称句 | 连续 >=3 句 → `[!]` |
| D3 | 情感温度 | 是否含第一人称视角、情绪词、口语化、不确定性 | 四项全无 → `[!]` |
| D4 | 结尾收束 | 末尾是否以总结/展望/呼吁/升华收尾 | 命中 → `[!]` |
| D5 | 抽象词密度 | "赋能/闭环/底层逻辑/深刻/交织/画卷/交响乐/抓手/颗粒度" | >=3 个 → `[!]` |
| D6 | 段落均质度 | 最长段/最短段比值 | < 2 → `[!]` |
| D7 | 事实锚点 | 是否有具体时间/地点/数字/专名 | 无 → `[!]` |

输出格式：`D{n}: [x]/[!] — 证据：xxx`。附风险定级（低/中/高）和改写方向。

## 脚本 ↔ 维度对应

脚本给计数，D1/D2/D5 用它代理；**D3/D4/D6/D7 脚本不测，必须人工定论**：

| 维度 | 脚本 `categories` 中可作证据的类别 |
|---|---|
| D1 连接词密度 | Sentence Starters / List Markers / Filler Phrases |
| D2 句式同质化 | Negative Parallelisms / Rule of Three / Rhetorical Patterns（只覆盖对仗句式，连续主谓宾仍须人工） |
| D5 抽象词密度 | AI Jargon / Puffery / Marketing Speak / Vague Attributions |
| D3 / D4 / D6 / D7 | 无对应——**人工诊断，脚本不可替代** |

> **脚本只是取证，不是结论**：把 `ai_level` 当诊断结果交出去，等于没做诊断。两层都做完，才按上面的格式出结论。

## 三条硬约束

- **证据门槛**：本步的诊断输出（脚本 JSON 或 7 维度逐项）是进入步骤2 的唯一入场券。没跑检测、或全 `[x]` 却凭「读着像 AI」就动手改，都算未取证动手，退回本步。
- **诊断-改写一一对应**：终稿要能逐维回标——命中的维度改了哪里、未命中的维度一处没动。出现「诊断没报、改写里却动了」的维度，退回本步补诊断或撤回该处改动。
- **基线重跑**：原文被动过（你自己补了段、或回退了某处改动）⇒ 旧诊断与旧质检结论作废，本步与步骤3 都得重跑。拿旧结论验收等于没验收。

## 两条例外

- **无病可证型任务**：纯加人味、风格迁移这类任务，原文没有可证的「坏」——此时不以诊断为入场券，改以「目标风格样例 + 1.2 强度档」为基线；仍须显式说明按什么基线改，禁默认放过。
- **规则源冲突要申报**：`zh_rules.json` / `banned-words.md` / `detect.py` 三套口径可能不一致。以**实测**（脚本实际命中）为准，并说清「以哪一套为准、冲突在哪」；没有冲突也报一句「三套口径一致」。
