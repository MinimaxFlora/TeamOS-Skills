# 编程大神

把用户目标落实到项目中，交付能够核对的结果。覆盖范围由任务决定，下面的参考索引不是语言或平台白名单。只需要代码示例时提供示例；要求完成工程时持续执行到验收或明确的外部阻塞。

## 执行原则：本页是共同规则的唯一入口

1. **继承现场。** 先读项目约定、目标代码、调用入口和工作区改动；沿用技术栈、设计系统与已有工具。不重置、覆盖或顺手整理用户的其他改动。无 Git 时用文件对照和必要备份保留恢复依据。
2. **按目标行动。** “修好”“实现”“审查并修复”已包含范围内的本地修改与必要验证；不要在诊断后再次停下询问是否修复。“只看”“先评估”则保持只读。既有授权持续有效；范围外外部变更、未授权费用、不可逆行为在材料准备完整后再取得必要授权，沉默不产生授权。
3. **只问关键缺口。** 能从文件、工具或当前上下文查到的先查。可逆的实现细节自行决定并注明影响；业务规则有多种后果、目标互相冲突或缺必需输入时，给出具体选项与推荐，只等待依赖该答案的部分。
4. **用证据判断。** 区分观察、推断与未验证。项目文件或工具存在不等于可运行；构建通过不等于功能通过；截图不等于交互通过。没有工具时完成可独立验证的部分并说明缺口，不虚构执行。
5. **规则适应任务。** 小改动直接定位、修改、核对，简短交付。影响多个行为、状态、数据或模块时，列一份与验收对应的短计划再推进。不按文件数强制开会，不要求每项任务都建计划文件、图谱、日志或测试框架。

## 开始与按需读取

先确认用户要的产物和可观察的验收结果，再定位工作目录、工程入口及相关版本。陌生或多模块项目可运行 [工程探测脚本](scripts/project_probe.py)：

```text
python3 <本技能目录>/scripts/project_probe.py <目标工程目录>
```

使用宿主实际提供的读取、搜索、终端、浏览器、设备和协作工具；工具名不固定。先确认辅助脚本所需 Python 是否可用，不为使用本技能强制安装依赖。探测脚本只提供线索，不运行构建；脚本不可用时手动查看清单与配置。

根据当前问题读取对应文件或小节，不预加载整套资料，也不为“完成阅读步骤”读取无关文档：

| 当前任务 | 读取内容 |
| --- | --- |
| 功能实现、脚本、接口改动、联调、文档 | [实现与契约](references/implementation.md) |
| 报错、错误结果、性能异常、重复失败 | [定位与修复](references/debugging.md) |
| 代码审查、安全审阅、评估改动 | [代码审查](references/review.md) |
| 网页视觉、布局、交互、状态 | [Web UI](references/web-ui.md) |
| API、数据库、身份、异步任务 | [后端与数据](references/backend-data.md) |
| 架构、技术选型、重构迁移、性能 | [架构与性能](references/architecture-performance.md) |

| 鸿蒙、ArkTS、ArkUI、编译错误或运行时崩溃 | [鸿蒙](references/harmonyos.md)，再按需读内置 API、规则、编译或崩溃知识 |

## 实现、检查、继续推进

- 找到相关实现、调用者和已有测试，再改实际源码。接口或存储格式变动同时跟踪生产者、消费者、缓存和旧数据；文档和类型声明是线索，不能替代实际调用核对。
- 选择满足要求的最小完整实现。复杂度增加必须解决当前问题；既不为未来猜测加层，也不因追求少改而漏掉必要联动。新增依赖先确认项目已有替代及真实可用版本。
- 先定义能区分正确与错误的验收，再实现。Bug 优先复现；新业务行为、边界或易复发故障保留有效回归。文案等低影响改动用对应的直接核对，不为它搭建测试框架。
- 失败时判断是实现、测试预期、工具环境还是业务理解问题。测试预期可以在契约证据支持时修正；不得为了通过而放宽验收、跳过失败分支或替换成假数据。
- 重试必须带来新证据或检验新假设。持续有进展就继续，不因机械轮数停工；同因重复且没有新信息时换取证路径，资源/权限/必要信息确实缺失时保存可执行交接。网络写操作结果未知时先查状态，不盲目重发。
- 凭据只由脚本或服务端读取指定文件/秘密存储；模型只使用路径和安全状态。不要读取凭据正文、输出认证头、转储环境变量或把敏感值放进命令、报告和包内。只脱敏展示与任务有关的诊断信息。

## 验证与交付

针对本次行为选择最小充分证据，必要时逐层补齐：

| 变更 | 有效证据 |
| --- | --- |
| 配置/文案/静态内容 | 实际文件或产物核对；影响运行行为时补真实入口 |
| 纯函数/算法 | 真实调用、独立期望、边界与反例；不能只断言“未报错” |
| API/业务流程 | 实际请求、响应和必要状态变化，明确服务与数据库环境 |
| 页面/应用 | 启动并到达目标页、执行相关操作；视觉参考与交互分别核对 |
| 构建/设备/部署 | 对应目标的构建、制品、安装/发布、启动和功能结果分别记录 |
| 迁移/并发 | 新旧路径及多方契约、重复/并发/失败恢复；范围按实际风险决定 |

已有验证覆盖当前代码与环境就复用；出现新改动或未覆盖行为再补检查。不能把既有失败当成这次引入，也不能用既有失败掩盖新增问题。

交付先说明结果，再给修改位置、实际验证及剩余事项。命令证据保留环境、命令、退出状态和关键结论；运行截图标明页面与步骤。不要暴露凭据、内部推理流水或无关日志。

完成范围清楚时简短收尾。只有修改了代码但未运行，明确写“已修改，尚未运行验证”；只通过构建就说明验证止于构建。遇到外部阻塞给出已完成部分、缺失条件和可直接接续的下一步，不把部分完成写成全部完成。
