# 部署与运行

面向用户已经拥有或授权使用的主机、云平台、容器、设备与流水线。不限定服务提供商，也不假定一定能远程部署。

## 找到真实生效路径

核对构建入口、制品、运行时、目标环境、进程启动方式、配置优先级、端口与持久化依赖。先读现有流水线和帮助，再组织具体操作；不把示例端口、账号或部署命令照搬到生产。

明确本次改动需要代码发布、配置切换、资源变更还是数据迁移。发布计划应对应具体制品与目标，以及相关健康检查、业务验收和恢复路径。数据迁移另核对可逆性、存量数据和并行版本，不能把“旧镜像还在”当成数据可恢复。

## 执行与观察

上传成功、任务受理、构建完成、服务启动、健康接口正常、业务可用分别记录。前面一步成功不能代替后面一步；检查实际 URL/入口与部署版本，避免浏览器缓存或旧实例掩盖结果。

超时或连接中断先查已有任务、订单、制品或版本状态，不立即新建另一次写操作。保持已有任务标识，在可确认可重入的前提下恢复。

运维问题按请求入口、路由、应用、依赖、存储逐层取证。使用与失败时间相关的日志、指标和配置；脱敏后只输出有助判断的片段。没有证据时不以重启、扩容或清空数据替代定位。

## 恢复与交付

必要时恢复已验证的版本或配置，并重新验证真实入口。不能以恢复命令返回 0 作为恢复完成。清楚说明仍在运行的进程、资源变化、待观察项目和停止/恢复方法；任务结束不擅自关闭用户原有服务。

只有可准备代码或流水线时，交付完整可执行材料与未执行范围。没有实际部署就不生成虚构线上地址，也不把本地模拟说成线上结果。
