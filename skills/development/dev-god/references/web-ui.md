# Web 页面与交互

涉及页面、组件或浏览器行为时读取；只改文案时只检查对应内容及其布局影响。沿用工程的框架、路由、组件和样式体系。新建页面先确定用户要完成的动作，再决定结构；不为展示设计能力强行换栈或重做邻近页面。

## 从真实页面开始

- 沿用户入口找到路由、页面、组件、数据请求及状态来源。先看实际页面和现有实现，区分“样式没生效”“数据没返回”“状态更新到了错误实例”。
- 有截图、设计稿或参考站时，在相近视口和相同状态下记录布局、字号层级、间距、颜色、图片裁剪与交互差异。参考没有展示的部分延续项目规范，不擅自增加装饰、虚构数据或客户背书。
- 定位元素时考虑 iframe、Shadow DOM、滚动容器和浮层；等待可观察的页面状态，不靠反复固定等待掩盖加载问题。

## 把状态写完整

- 按本次功能检查加载、空结果、成功、失败及权限不足的呈现；保留用户输入和可重试入口。提交按钮禁用可改善体验，但不能代替服务端幂等。
- 快速搜索、切换详情或离开页面时，防止旧请求覆盖新状态；取消请求或校验请求归属。分页、筛选与返回导航使用明确的状态来源，避免旧页面状态串入新内容。
- 表单校验同时覆盖客户端提示与服务端错误；弹窗关闭后恢复合理焦点，键盘可到达操作控件，错误不能只靠颜色传达。
- 布局用真实长标题、空字段、大数值和图片加载失败检验。定位溢出的具体元素，不用全局隐藏滚动掩盖裁切；检查窄屏、放大文字、软键盘和固定底栏是否挡住操作。

## 用行为与视觉分别核验

从实际页面进入，执行受影响操作，核对跳转、请求、结果和持久化后的回显；涉及刷新、返回或多次提交时，覆盖相应路径。模拟数据只能证明对应模拟场景，不能证明联调成功。

截图在页面稳定后采集，与参考或修改前页面使用相同视口、滚动位置和数据状态；先修结构与内容差异，再修间距、颜色等细节。DOM 和布局树可解释元素位置，不能代替视觉观察；截图也不能证明按钮可用。

若只有构建环境，完成可运行的局部检查，并把浏览器交互与视觉验收留作明确待验证项。无需为了一个已有组件的小改动新建整套设计系统或视觉回归框架。
