# ReferenceError：引用与初始化

改编自上游同名知识文件；先遵循[证据与来源约定](index.md)。

| 线索 | 候选与确认 | 最小修复 | 复验 |
| --- | --- | --- | --- |
| `missing @Provide property` / `Fail to resolve @Consume` | 实际组件祖先链上缺少匹配提供者，名称/别名、挂载位置或初始化次序可能不符 | 对照该 SDK 与当前状态管理版本，修正应拥有数据的提供者和消费关系 | 直接进入、返回再进、条件挂载 |
| `duplicate @Provide property` / `override not allowed` | 实际祖先链上的重复名称与当前装饰器配置冲突 | 确认共享数据意图后改别名或移除重复；不要凭词条删除业务状态 | 多实例和嵌套组件，确认同步对象正确 |
| `is not initialized` | 初始化前访问、循环依赖或生命周期路径不完整 | 修复赋值与使用顺序；区分“尚未就绪”和业务允许的空值 | 冷启动、慢异步、销毁重建 |
| `<name> is not defined` | 作用域、符号导入、产物版本或条件路径问题 | 沿应用栈追溯声明与构建产物，不用任意全局变量代替 | 原入口、相关条件路径 |

`@Provide` / `@Consume` 的规则不能直接套到其他状态管理装饰器；覆盖能力、别名和默认值以实际 SDK 与源码声明为准。空值保护只有在业务允许该状态且 UI/调用方能够正确处理时才是完整修复。

构造函数 `super()` 线索见[总表](fault-mode-library.md)。
