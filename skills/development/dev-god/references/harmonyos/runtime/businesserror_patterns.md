# BusinessError：接口失败

改编自上游同名知识文件；先遵循[证据与来源约定](index.md)。

先确认**具体模块、API、SDK、code、message 和调用栈**。BusinessError 表示接口报告失败，单独出现不证明进程崩溃；同一数字必须在该 API 的错误码表中解释。下列只是上游收录的线索，不是全部原因。

| 线索 | 候选与确认 | 最小修复 | 复验 |
| --- | --- | --- | --- |
| `Parameter error` | 参数类型/范围、缺少必填项或错误重载；检查实际实参 | 在输入边界修正契约并处理不合法输入 | 有效、缺项、边界和错误类型 |
| JSON 相关文本或内部 `SyntaxError` | API/业务可能包装了解析失败，不能凭文本确定是谁重抛 | 查包装位置与原始输入来源，处理解析失败而保留原因 | 正常、截断、非 JSON 响应 |
| `unterminated entity ref` | XML/HTML 解析链中实体或转义可能不完整 | 根据实际格式和序列化器修复生成端，避免二次转义 | 特殊字符、已转义输入、合法实体 |
| `Invalid Url string` / `Invalid Uri string`（上游示例含 `10200002`） | 当前 URL/URI API 不接受该输入 | 核对使用的解析器、允许形式和编码规则；不能把某个片段位置一概判非法 | 实际支持的相对/绝对形式、中文、片段、百分号 |
| 其他 code/message | 权限、系统能力、服务状态、对象生命周期等仍是候选 | 查本 SDK 的具体 API 合约，验证前置条件；不把所有错误都归结成参数错 | 成功路径及被拒绝/不可用状态 |

若接口返回 rejected Promise，处理对应异步失败；同步 `try-catch` 不能自动捕获未等待的异步拒绝。修复后验证业务可恢复状态和原崩溃路径，勿只验证日志不再输出。
