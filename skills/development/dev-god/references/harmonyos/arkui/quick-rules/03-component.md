# 自定义组件与命名

- `@Component` 与 `@ComponentV2` 不装饰同一 struct；按工程状态体系选择。struct 不是普通可继承的业务类。
- 一个页面入口保持一个 `@Entry`；多页面 Router 工程可以分别有入口，不要求全应用只保留一个。
- 同一作用域避免覆盖系统组件和已导入类型。不同模块的同名类/interface 可以独立存在；诊断为声明合并时先查是否缺少模块边界或发生真实重名，不强制每个类名加全项目唯一前缀。
- 生命周期函数（如 `aboutToAppear`、`aboutToDisappear`）应按官方签名实现，用于对应时机的业务处理。**它们不是禁止定义的业务保留字。** 不另定义 `rerender`、`initialRender`、`getUIContext` 等框架内部实现来覆盖运行时。
- 普通局部变量叫 `value`、`builder` 不因此违法。若组件成员与生成的属性/方法产生实际冲突，依据诊断用业务名消歧义，不把所有链式属性名列为语言关键字。
- 不依赖 V1 struct 的静态代码块做应用初始化；共享初始化放在可验证的模块/Ability 生命周期。对访问器、访问修饰符和静态成员，检查当前组件编译模式的支持范围。
- 组件构造使用 UI 描述调用，控制器等普通类使用 `new`。
